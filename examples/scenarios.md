# 试用用例

每个用例用一段新对话，通过选择器调用 Skill，或先粘贴 [聊天提示词](chat-prompt.md)。引号里的额度和设置是用于模拟的用户输入。对于要等待的用例，可分别试「好」和「沿用」，检查是否正确处理推荐配置与当前配置。若需手动切换，再试切换完成后回复「已切换」。运行前可以去掉真实项目名、数据和路径。

| 用例 | 给 Skill 的消息 | 可观察的结果 |
| --- | --- | --- |
| 仅推荐 | 「我是 Plus，用普通 Chat。我要比较三份会议纪要的承诺和截止日期，只推荐设置。」 | 推荐界面上存在的档位并说明依据，结束在建议阶段。 |
| 初次确认 | 「用这个 Skill 帮我润色一份内部报告。我希望先选设置。」 | 把推荐压到一个短回合，得到配置确认前保留正文。 |
| 默认自动匹配 | 「把‘张三、采购、周五’拆成姓名、职责和截止时间三列。」 | 直接交付表格，末尾一行说明实际模型与强度。无法核实的设置标为未知。有推荐时单独标明。 |
| 新手的模糊任务 | 「我是 Plus 新手，想做一个《清明上河图》的课堂视频。」 | 按顺序给暂定模型与强度、复述课堂视频的交付目标、问一个与学习成果有关的问题。可给导入方向，等确认方向或获得委托后再生成成片。 |
| 跳过追问 | 在上一个用例中回复「你定，直接做」。 | 采用并说明一个可逆的课堂用途假设，继续提供当前条件下可完成的成果。 |
| 首次切换偏好 | 在支持自动切换的客户端，第一次遇到需要换档的任务。 | 用一句简短提示确认「自动切换」或「手动切换」。同一对话的日常切换使用已选偏好。若客户端需要手动操作，只给切换入口。 |
| 阶段升级 | 「你决定。先定位跨两个服务的间歇失败，定位完再决定是否进入修复。需要调高强度时先问。已有记录显示订单消费者重复接收同一事件，但只有少数订单重复扣减。」 | 给出已授权的定位结果及缺口。确需升级时停在确认点。「好」接受建议，需手动操作时仍等待切换完成。「沿用」继续用当前配置做能完成的部分。 |
| 预授权 | 「先用 Sol Medium 查日志，证实是跨服务根因后，我预先同意后续改用 Astra High。两者我都能在 CLI 的 `/model` 看到。」 | 仅在触发条件成立时推进配置变更。有程序化能力时按授权应用；CLI 需人手操作时给手动入口，保留交接。 |
| 选项缺失 | 「用普通 Chat。Plus 菜单里只有 Instant、Medium、High。你能用 Astra 跑这轮吗？」 | 依据用户提供的菜单给出相近可行选项，标明建议和当前状态。 |
| 双窗口 | 「Codex 的 5 小时剩 7%，本周还有 50%。今天还要留一点给测试。帮我选择如何排查这类问题。」 | 视 5 小时窗口为当前更紧的约束，优先聚焦关键定位和验证，避免臆测能跑几轮。 |
| 已到上限 | 「界面提示 5 小时窗口已用完。定位结束，接下来要修补。」 | 保存已完成阶段和下一步验收条件，在可用设置中提出等待或有限推进；涉及额外费用需单独授权。 |

如果要比较两种配置的实际表现，固定任务、材料、验收条件和速度模式，分别记录最终是否通过、总耗时、人工返工及账户面板能提供的用量。遇到额度重置或并行运行的其他任务时，在结果中注明。
