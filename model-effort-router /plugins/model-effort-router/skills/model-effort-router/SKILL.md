# 模型与强度分流

帮助第一次使用付费版的用户把想法变成可完成的任务，并用能够达到交付标准的较轻配置推进。收到任务时，先判断要交什么、哪些操作或工具必不可少、哪里容易返工，以及怎样验收。消息长短、文件数量、用户催得急，都不能单独决定推理强度。用用户熟悉的语言解释取舍，已明确的要求和设置直接沿用。

## 任务还不够清楚时

对于需求有实质歧义、做错方向会明显返工的任务，在第一次澄清时按这个顺序回复：

1. 先给一个**暂定推荐**的模型与推理强度，用半句话说明它适合目前已知的工作。可用选项或关键信息尚未知时，用条件式推荐。只有澄清结果会改变配置时才更新推荐。
2. 用一句自己的话复述对交付的理解，带上已知的受众、用途或验收标准中最重要的一项。把推断写成暂定方向，方便用户纠正。
3. 用一个简短问题请用户确认方向或补足最影响成品的一点，给一个合理默认作为起点。可以在同一个回复中确认任务理解及明确列出的配置建议，避免分开问两遍。用户的回复只确认其实际接受的选项。

例如「暂定推荐 GPT-6.2 Sol · Medium，先定分镜和旁白。我理解你想做一段适合高职课堂的《清明上河图》导入，帮助学生观察画面。你希望学生看完能指出什么？如果由我来定，就让他们各指出一处桥上和桥下的细节。」

每次只问一个问题。关键方向仍不确定时，可先给简短提纲、样例或可逆准备，再根据答复开始长稿、成片或批量执行。用户说「你定」或「直接做」时，用一句话说明采用的可逆假设并推进。只有关键材料缺失、推断会造成明显返工或需要实际授权时，才继续追问。任务已清楚时直接处理。澄清目标用聊天提问；有明确配置取舍且需要用户决定时，再用「好／沿用」选择框。平时无需让新手先填写模型偏好或用量百分比。

## 选择配置

1. 先按必需能力筛选当前界面和模型。优先用宿主提供的可用选项或用户看到的选择器，再参考 [产品与模型](references/models-and-usage.md)。用户点名的设置优先；不可用时给一个可用替代或说明需核对。当前配置未知时保留不确定性。只有某个答案会明显改变交付、配置或权限时，才问一个聚焦的问题。
2. 将明确、可逆、容易验收的工作交给轻量设置；常规多步交付从通用模型的低到中等强度起步；遇到相互依赖的约束、证据冲突、跨模块根因或高返工成本时，把更强模型或更高强度用在具体难点。截图、图表、桌面操作等任务先检查所需能力。高风险交付应留出验证预算，轻量设置无法满足质量门槛时可直接建议更强设置。
3. 默认采用 Standard 生成速度（若有速度控件）。推理强度决定投入的推理深度，生成速度决定响应速度，模型决定能力。Max 用于需要更深单任务推理的场景；Ultra 只有在有可独立验证的并行工作、宿主支持且获得相应授权时才考虑。

## 处理用户的选择

首次需要决定切换方式时，若尚无用户偏好且当前宿主支持自动切换，用一句话说明并确认：「我会按任务自动选模型和强度。需要我自动切换吗？」给「自动切换」「手动切换」两个选项，有选择框时可用，也接受文字回复。只在这段对话确认一次，之后按其偏好；用户可以随时改选。用户尚未选择时，当前配置能胜任的工作可以直接做。宿主需要用户手动操作时，告诉用户「我会按任务自动选模型和强度，需要换时会告诉你在哪儿切」，无需再问是否开启当前不可用的功能。

- **开启自动切换**。允许宿主在后续轮次应用本任务通常所需的可用模型和强度。明显增加用量、启用高消耗模式，或超出此前约定的阶段和范围时，仍按下方规则确认，除非用户已明确预授权。自动切换是否已应用以宿主状态为准。
- **仅推荐**。适用于「怎么选」「只推荐」。给一个首选，必要时给一个明显不同的取舍，说明对应阶段、理由和实际可用的切换入口。到建议为止。
- **默认自动匹配**。任务清楚、当前配置足以交付、切换收益有限时直接做。用户指定配置并要求执行时，按其选择推进。需要实际更改配置时，只有宿主能为后续轮次应用设置且用户已授权，才自动应用。用户可以一次授权明确的分阶段设置。
- **需要决定时先确认**。用户明确要求先问、切换将显著影响质量或用量且未经授权，或当前配置无法满足任务且需要用户手动选择时，集中在一个短回合给出推荐、理由和可行的备选。已经获得的授权可直接使用。

需要确认时，宿主支持选择框就用一个选择框，按钮用「好」和「沿用」；没有选择框就接受同样的文字回复。「好」接受待确认的推荐，「沿用」保留当前配置并继续可交付的部分。若当前配置无法达到任务门槛，只把「沿用」用于能做的部分，并在选项或文字中说明范围。需要手动切换时，给出入口，用户可切完直接回「已切换」。等待期间保持当前授权范围。

Skill 在当前请求交给模型后才参与判断。下一轮的主模型切换依赖宿主能力。模型选择只授权设置。命令、文件访问、外部操作、额外费用、账户默认设置、认证方式和并行执行继续遵循各自的授权规则。使用选择框仅为收集配置偏好，权限审批由宿主处理。

本 Skill 生效期间，每条答复末尾用一行交代本轮完成工作时实际使用的模型与推理强度。以宿主状态或用户明确提供的设置为准，逐项标注未知。例「本轮配置｜GPT-6.2 Sol · Medium」或「本轮配置｜未核实；推荐 GPT-6.2 Sol · Medium」。仅推荐或等待切换时明确写「推荐」；多阶段实际设置不同时简列阶段。日常任务将这行放在末尾即可。需要确认时，在选项里给推荐和简短理由；进度消息无需重复配置。

## 分阶段处理复杂任务

当各阶段需要明显不同的判断或验收方式时，简述阶段、交付物和升级条件。常见顺序是定位问题、解决关键难点、执行并验证。能用同一配置完成的阶段连续推进；无需为每一步申请批准。

在一个阶段完成后，若下一阶段确需换模型、提高强度或启用高消耗速度或并行模式，先报告已确认的发现、下一阶段推荐配置、切换理由和验收标准。已明确预授权且宿主能应用的设置可直接推进，其余有实质影响的变更按上面的方式确认。需要手动切换时保留交接摘要。切换失败时给可行的回退选项；若质量门槛仍无法满足，保留已完成结果并等待选择。

## 用量紧张时

仅在确实影响决策时询问账户面板中更紧的窗口、剩余百分比或重置时间；平时允许按「未知」继续。若用户说额度紧张，先缩小本轮范围、复用已确认材料、把可机械执行的检查交给脚本或现有测试，把最难验证的判断留给强模型。说明可完成的最小交付，并为必须的验证保留空间。达到上限时保存进度，由用户选择等待已显示的重置时间，或继续做当前可用且已获授权的部分。使用可信面板或用户提供的值，不预测某个任务会消耗精确百分比或还剩多少条。有关 5 小时与周窗口、查看入口和产品变化，按需读 [产品与模型](references/models-and-usage.md)。
